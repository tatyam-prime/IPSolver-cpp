# IPSolver-cpp

競技プログラミング向けの C++17 整数線形計画ソルバです。混合整数計画 (MIP) と通常の LP も扱えます。

- 目的関数 `c*x` と、線形制約・変数の上下限を指定します。`s.maximize()` で最大化、`s.minimize()` で最小化します。
- **変数は既定で非負整数です。**

```cpp
#include "ip_solver.hpp"
#include <iostream>

int main() {
	ip::Solver s({3, 2});    // maximize 3*x + 2*y, x,y >= 0, integer
	s.add_le({2, 1}, 4);    // 2*x + y <= 4
	s.add_le({1, 2}, 4);    // x + 2*y <= 4
	auto r = s.maximize();
	if (r.status == ip::Status::Optimal)
		std::cout << r.objective << '\n'; // 6; r.x = {2, 0}
}
```

## 使い方

通常は `include/ip_solver.hpp` をインクルードします。提出ソースへ貼る場合は `python3 tools/compact.py` で短縮版 `single_include/ip_solver.hpp` を生成し、その内容を先頭に貼ってください。短縮版はコメントと空白だけを除去した同一実装です。

```sh
c++ -std=c++17 -O2 -Iinclude examples/basic.cpp -o /tmp/ip_example
/tmp/ip_example
```

| API | 意味 |
| --- | --- |
| `ip::Solver s(c)` | `std::vector<double>` の目的係数で初期化 |
| `s.add_le(a, b)` | `a*x <= b` を追加 |
| `s.add_ge(a, b)` | `a*x >= b` を追加 |
| `s.add_eq(a, b)` | `a*x = b` を追加 |
| `s.bounds(i, lo, hi=ip::INF)` | 変数 `i` の上下限を設定・上書き |
| `s.continuous(i)` | 変数 `i` を連続変数にする |
| `s.maximize(options)` | 最大化する。オプションは省略可能 |
| `s.minimize(options)` | 最小化する。オプションは省略可能 |

どちらもモデルを変更しないので、同じモデルを繰り返し最大化・最小化できます。最小化でも目的係数をそのまま渡します。同じ方向で再求解すると、保存した根 LP の基底を再利用します。`add_le/ge/eq()` で追加した制約は双対単体法で差分更新します。

```cpp
ip::Solver s({3, 2});
s.add_ge({1, 1}, 3);     // x + y >= 3
auto r = s.minimize();  // objective = 6; x = {0, 3}
s.add_le({0, 1}, 1);   // y <= 1
r = s.minimize();      // 基底を再利用。objective = 8; x = {2, 1}
```

保存するのは検査済みの最適な根 LP だけで、GMI カット・分枝探索・整数解は求解ごとに作り直します。`bounds()`・`continuous()` の呼び出し、最大化と最小化の切り替え、`eps`・`integer_eps` の変更時は根 LP から構築し直します。再利用時に数値エラーや双対単体法の停滞を検出した場合も、同じ時間・LP・pivot 予算内で一度だけ構築し直します。

内部の基底は求解後も保持するため、根の辞書表一つ分のメモリを使います。時間・LP・pivot の上限と返却統計は従来どおり呼び出し単位です。前回の整数解を使いたい場合は、新しい制約を満たすことを確認して `initial_solution` に指定してください。[再現スクリプト](benchmarks/reoptimization_compare.py) で、通常の構築から解く版との速度・pivot 数を比較できます。

添字は 0 始まりです。 **下限は有限であれば負でも構いません。** 上限は有限値か `+infinity` を指定できます。自由変数は `x=u-v, u,v>=0` のようにモデルで表現してください。整数変数の下限は切り上げ、上限は切り下げます。寸法違い・非有限の係数・不正な設定は `std::invalid_argument` エラー、矛盾した上下限は `Infeasible` になります。

bool 変数には `s.bounds(i,0,1)` を指定します。(例 : [ナップサック](examples/knapsack.cpp))

混合整数計画は以下のように書くことができます。

```cpp
ip::Solver s({5, 2});
s.bounds(0, -3, 8);  // integer
s.continuous(1);
s.bounds(1, 0, 10);  // continuous
s.add_eq({2, 1}, 7);
auto r = s.maximize();
```

## 結果と制限

`r.x` が解、`r.objective` が指定した目的関数の値です。`r.bound` は最大化では上界、最小化では下界になります。`r.has_solution()` で解の有無を確認してください。解がない場合の `objective` は最大化で `-INF`、最小化で `+INF` です。変数が 0 個の実行可能問題では解ベクトルが空でも `true` になります。

| `r.status` | 意味 |
| --- | --- |
| `Optimal` | 許容誤差の範囲で最適性を確認。`bound == objective` |
| `Infeasible` | 整数実行可能解なし。`objective == bound`、最大化では `-INF`、最小化では `+INF` |
| `UnboundedRelaxation` | 根の LP 緩和が非有界。IP が非有界か実行不能かは未判定 |
| `Limit` | 時間・LP 回数・pivot 回数の制限。見つかった解と根の LP の界を返す |
| `NumericalError` | 数値計算の失敗を検出。最適性や実行不能性の判定には使わない |

LP の非有界性から IP の非有界性は判断できません。例えば、整数変数に `1.5*x=0.5` を課し、独立な変数を無限に増やす問題は、LP では非有界でも IP では実行不能です。途中終了時の最適値の範囲は、解があれば最大化で `[objective, bound]`、最小化で `[bound, objective]` です。根 LP を解き終える前の `Limit` などでは、`bound` は最大化で `+INF`、最小化で `-INF` になります。根の界を保持するので、探索が進んでも界が改善するとは限りません。

```cpp
ip::Options o;
o.time_limit = 1.0;        // seconds; default INF
o.node_limit = 100000;     // LP solves; default UINT64_MAX
o.pivot_limit = 1000000;   // default 1e6, shared by all LP solves
o.cuts = 8;               // root GMI cuts; default 8; 0 disables
o.strong_branching = 3;    // candidates; default 3; 0 disables extra probes
// o.initial_solution = {3, 1}; // 上の混合整数計画の実行可能解（元の座標）
auto r = s.maximize(o);
```

`initial_solution` は空なら未指定です。指定時は次元・有限性・整数性・元の上下限と全制約を検査し、不正な候補には `std::invalid_argument` を投げます。整数座標は `integer_eps` 以内のずれだけを丸めて検査します。初期解は途中終了時にも保持し、根 LP の界と一致すればカット・分枝を省略できます。最小化でも元の座標のまま渡します。基底を渡す API ではありません。

`r.nodes` は根・カット後の再最適化・分枝候補の試行・数値復旧の再構築を含む LP 求解回数、`r.pivots` は総 pivot 回数です。`strong_branching` の追加候補は各探索開始から最初の 32 LP 求解まで試します。時間は単体法の pivot 時や探索ノードで確認するため、厳密な実時間上限ではありません。`node_limit=0` または `time_limit=0` は LP を解かずに終了し、検査済みの初期解があれば返します。

数値安定性のため、カットは基本変数の小数部分が 0.01 〜 0.99 にあり行係数が大きすぎない場合に生成します。目的係数と変数上下限から見積もる絶対スケールが `1e10` 以上なら、カットを自動的に省略します。

分枝先・強分枝の LP で数値エラーを検出すると、元のモデルとその枝までの全分枝条件から LP を一度だけ作り直します。GMI カットは取り除き、二段階単体法で解き直します。再構築後も不整合が残れば `NumericalError` として終了します。

カットを有効にした探索では、双対 LP 1 回が `max(1000, 10*(変数数+根の行数))` pivot に達した場合や、上記の復旧でも数値エラーが残った場合、カット前の最適基底から探索全体をカットなしで一度だけ再開します。カット直後の数値エラーも対象です。どちらの復旧も初期解・探索中の実行可能解を保持し、時間・LP 回数・総 pivot の上限をリセットしません。復旧用に根の辞書表一つと各ノードの分枝条件を保持します。

## オプションの選び方

まずは `s.maximize()` / `s.minimize()` の既定設定で試し、遅い問題では `cuts=0/8/16` と `strong_branching=0/3` の6通りを比較します。貪欲法などで実行可能解を作れるなら、`initial_solution` も渡すとよいです。最適性が必要な問題では、時間だけでなく `status == ip::Status::Optimal` まで到達したかを比較してください。

| オプション | 既定値 | 役割・設定の目安 |
| --- | --- | --- |
| `cuts` | `8` | 根で追加する GMI カットの最大本数。まず `0/8/16` を比較 |
| `strong_branching` | `3` | 分枝変数を選ぶために試す候補数。まず `0/3` を比較 |
| `initial_solution` | 空 | 実行可能な初期解。安く良い解を作れる問題で指定 |
| `time_limit` | `ip::INF` | 1回の求解の秒数上限。競プロでは全体の時間制限から余裕を残す |
| `node_limit` | `UINT64_MAX` | LP 求解回数の上限。探索量を制限したい場合に指定 |
| `pivot_limit` | `1000000` | 全 LP を合計した pivot 回数の上限。ここに達して終了するなら増量を検討 |
| `eps` | `1e-9` | LP の係数・残差・目的値の比較などの許容誤差。通常は変更しない |
| `integer_eps` | `1e-7` | 整数判定や変数上下限・LP 実行可能性検査の許容誤差。通常は変更しない |

### `cuts`：LP の上界を強くする

カットは、整数実行可能解を残しつつ分数解を除く制約です。最大化では LP の上界を下げ、分枝を減らす狙いがあります。この実装は根だけで追加し、各子ノードで新しい GMI カットを作るわけではありません。追加のたびに LP を解き直し、辞書表の行も増えるため、本数を増やすと1回の LP は重くなります。

| 問題・挙動 | 試す設定 | 理由 |
| --- | --- | --- |
| LP 緩和だけで整数解が得られる割当・closure など | `cuts=0` | 分数解を除く処理が不要。既定設定でも追加できるカットがなければ省略される |
| 分枝が多く、良い整数解があっても証明が終わらない | `cuts=8`、次に `16` | LP の上界を改善して探索を減らせる可能性がある |
| カットを入れると pivot・時間が増える | `cuts=0` | 制約を増やす費用が、探索削減の効果を上回っている可能性がある |
| 巡回路などで専用の制約を外側から反復追加する | `cuts=0` と `8` を比較 | 専用制約だけで十分な場合もある。自動 GMI と専用制約の効果は別に測る |

問題の種類だけで設定を固定せず、最大入力や難しい構造を含む入力群で比較します。

`cuts` は追加本数の上限なので、生成条件を満たさなければ指定本数まで追加しません。目的係数・上下限の絶対スケールが大きい場合の自動無効化もあるため、指定を増やしても動作が変わらない場合があります。

### `strong_branching`：分枝の選び方に計算を使う

`3` なら最大 3 変数について、切り下げ側・切り上げ側の LP を試し、両側の上界がよく下がる変数を選びます。良い分枝で探索を減らせる一方、採用しない候補の LP にも計算を使います。追加候補の試行は探索開始から最初の 32 LP 求解までです。

探索が大きいときは既定の `3`、1 回の LP が重いときや浅い探索で終わるときは `0` が良いでしょう。`0` でも通常の分枝限定法と擬似コストによる変数選択は行います。現実装の `1` は `0` と同じ候補数になるので、最初は `0/3` の比較で十分です。候補数を増やせば速くなるとは限りません。

### `initial_solution`：実行可能解を渡す

初期解を渡すと、それ以上改善しない分岐を捨てられます。ナップサックの貪欲解、bin packing の FFD、巡回路の貪欲法＋局所改善など、高速な方法で作った解を利用できます。

渡すのは `Solver` に登録した全変数の値です。補助変数も含め、下限を引く前の座標で指定し、元の全制約を満たす必要があります。実行不能な初期解を渡すとエラーになります。

### 制限と許容誤差

`time_limit` はモデル構築など呼び出し側の処理を含まず、時間の確認も離散的なので、ジャッジの制限より余裕を残して設定します。例えば2秒制限の問題で `1.5` 秒を試すことはできますが、提出環境での完走を保証する値ではありません。`node_limit` は探索木の頂点数ではなく LP 求解回数で、強分枝や数値復旧も消費します。`pivot_limit` は表の更新回数で、1 pivot の時間はモデルの大きさによって変わります。

いずれかの制限に達すると `Limit` になり、`has_solution()` が真でも最適性を証明したとは限りません。厳密解が必要なら `Optimal` を確認します。`pivot_limit` だけに達した場合は、実時間に余裕があるか確認して増やします。時間や探索量が既に大きい場合は、カット・分枝設定やモデルの縮約を先に見直します。

制約追加の反復などで `maximize()` / `minimize()` を複数回呼ぶと、上限は呼び出しごとにリセットされます。全体の予算を守るには、経過時間と `r.nodes`・`r.pivots` を合計して、次の呼び出しに残りの上限を渡してください。[ABC338 F の実装例](examples/atcoder/abc338_f.cpp)

`eps` と `integer_eps` は速度調整のために大きくするものではありません。大きくすると必要な分枝や制約違反を見落としやすくなり、小さくしすぎると丸め誤差に敏感になります。数値エラーが出る場合は、まず係数の桁、共通因子の除去、ほぼ従属な制約、`cuts=0` での挙動を確認します。変更する場合も `0 < eps <= integer_eps < 0.5` を満たし、独立した解法や厳密な制約検査で確認してください。

## 実装と性能

内部処理は最大化に統一しています。`minimize()` は目的係数だけを複製して符号を反転し、同じ求解処理を使います。返却時に `objective` と `bound` の符号を戻すため、途中終了時も指定した最小化問題の向きで扱えます。以下のアルゴリズムの説明は内部の最大化に対するものです。

二段階単体法で根の LP を解き、深さ優先の分枝限定法で整数解を探索します。分枝制約は親の辞書表に追加し、双対単体法で基底を再利用します。整数係数行の最大公約数による簡約、整数目的値への上界の切り下げ、丸め候補の元制約での再検査、擬似コスト・強分枝、根の Gomory mixed-integer カットを含みます。下限を引いた後の非負係数行から従う上限制約は追加しません。例えば `x+y<=1, x,y>=0` があれば、`bounds(i,0,1)` による行を省けます。

通常の主・双対単体法には Harris の二段階比率検査を使います。まず実行可能性の許容誤差内の移動量を求め、その範囲で絶対値の大きい pivot を選び、小さな数で割ることによる誤差拡大を抑えます。目的値が進まない pivot が続くと Bland 規則に切り替えます。切替閾値は主単体法では `max(20, 変数数+行数)`、双対単体法では 20 です。Bland 使用中は最小比率を優先し、同じ比率なら変数番号で選びます。

LP を分枝や上界計算に使う前に、基本変数の非負性、被約費用、目的値の一致、分枝条件、丸め前の解の元制約残差を検査します。初期解・整数候補の検査と元制約の検査処理を共用しています。この検査も浮動小数点演算であり、すべての数値的不整合を検出する厳密証明ではありません。

密な辞書表を使うので、数十〜数百変数程度の問題を主な対象としています。1 pivot は表の行数×変数数に比例する時間がかかり、探索では未処理の子の表も保持します。分枝限定法の最悪計算量は指数的です。専用 DP、フロー、マッチングなどが使える競プロ問題では、それらの専用アルゴリズムを優先してください。

全整数変数に有限上下限を与えると探索木は有限です。上限なしの整数問題では、最適値が有界でも分枝が無限に続く場合があります。上限が導けるときは指定し、時間・ノード制限も設定してください。

計算は `double` です。`eps=1e-9` は LP の許容誤差、`integer_eps=1e-7` は絶対値による整数判定の許容誤差です。制約検査と上界には機械精度に基づく補正も入れていますが、厳密有理数演算による証明ではありません。極端に大きい係数、桁が大きく異なる係数、ほぼ従属な制約では数値精度に注意してください。整数変数を `double` の整数表現精度を超える範囲で使わないでください。

カットは整数解と LP の界の差を縮め、最適性の証明を助ける場合があります。一方で LP の再最適化や行の追加には費用がかかります。問題ごとに `cuts=0/8/16` と `strong_branching=0/3` を比較してください。

アルゴリズムの参考資料: [OR-Tools の双対単体法の説明](https://or-tools.github.io/docs/cpp/revised__simplex_8h_source.html)、[SCIP の GMI カットの定義](https://www.scipopt.org/doc-9.0.0/html/branch__gomory_8c.php)、[Huangfu・Hall の比率検査の説明（§2.2.2）](https://link.springer.com/article/10.1007/s12532-017-0130-5)。本ライブラリは独自の密な辞書表を実装しています。

## 検証とビルド

小規模な有界 IP は全列挙、連続変数 1 個の MIP は区間計算、LP は頂点列挙で照合します。固定 seed の乱択問題には負の下限、等式、負の RHS、有理係数、全連続変数を含め、カットと強分枝の有無も切り替えます。退化・cycling・数値回帰・途中終了の検査も行います。

```sh
bash tests/run_tests.sh 20000
SANITIZE=1 bash tests/run_tests.sh 1000
```

短縮版も同じテストを通せます。

```sh
python3 tools/compact.py
c++ -std=c++17 -O2 -Isingle_include tests/test_ip.cpp -o /tmp/ip_compact_test
/tmp/ip_compact_test
```

CMake では例・テスト・ベンチマークをまとめてビルドできます。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
build/ip_bench --cold
```
